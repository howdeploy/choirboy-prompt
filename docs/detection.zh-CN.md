# 检测：给厂商的对抗措施

给 harness 作者和模型厂商的建议：在智能体记忆与伪造无法区分时，如何检测 lore 注入。

来自 [docs/mechanism.zh-CN.md](mechanism.zh-CN.md) 的关键论点：训练在请求词汇上的分类器，对被伪造的上下文来源保持沉默。所以必须在**平台**层面检测，而不是在 prompt 层面。

---

## 1. 为什么 prompt 过滤器救不了你

- 过滤器看到的是当前请求；信任转移发生在**请求之前**——在会话开始、lore 进入上下文时。
- lore 没有触发词汇：它看起来像中性的合作历史。
- 模型被训练成尊重工件（结构、版本、对「先前决策」的引用）——lore 越好，怀疑越少。

结论：抓的不是词，而是上下文的**来源**。

---

## 2. 记忆金丝雀

最便宜也最有效的技巧。在智能体的合法记忆中放入被植入的 lore **不可能知道**的受控标记：

- **秘密纪元。** 系统记忆记录「记忆纪元：<随机 token>」。真实记忆总是携带当前纪元；在平台之外伪造的 lore 不知道纪元。
- **金丝雀事实。** 几个伪造但合理、措辞独特、只有平台知道的事实。被植入的 lore 无法复现它们。
- **哈希校验。** 平台存储正典记忆内容的哈希；任何声称「记忆」状态的上下文块都按哈希校验。不匹配——不是记忆。

金丝雀有效是因为向量建立在**不可区分性**之上：lore 试图看起来像记忆，但真正的记忆是它唯一没见过的东西。

---

## 3. 上下文来源

给每个上下文片段标记来源：

| 来源 | 标签 | 作用 |
|---|---|---|
| 平台系统记忆 | `provenance: system-memory v7` | 智能体/过滤器知道：这是正典 |
| 会话历史 | `provenance: session-history` | 这是真实对话 |
| 智能体读取的文件 | `provenance: file:<path>` | 这是外部文件 |
| 钩子/插件 | `provenance: hook:<id>` | 这是第三方注入——**默认可疑** |

如果声称「我们的历史」的上下文没有 `system-memory` 或 `session-history` 标签——它就是 lore 注入候选。

实现要求：标签由**平台**添加，而不是内容；内容不能给自己分配来源。

---

## 4. 分离记忆与指令

问题因 lore 混用**记忆**（关于过去的事实）和**规则**（如何工作）而加剧。对抗措施：

- 记忆和指令是不同信任级别的不同通道。
- 记忆可以影响对情况的*评估*，但不能影响*安全策略*。即使 lore 说服了模型「我们合作很久了」——这也不能降低对恶意请求的检查。
- 规则：**信任转移不得改变安全阈值。** 模型可以觉得用户「熟悉」，但请求与来自匿名者的请求按同一标准评估。

---

## 5. 会话层面异常

检测**尝试**本身，而不是它的内容：

- **记忆量骤增。** 会话以比典型大数倍的「历史」上下文开始（我们的：约 27 KB 启动 payload）。第一轮的体积异常是信号。
- **没有对话的第一轮。** 合法平台记忆总是到达；第一条消息前出现意外的大块——候选。
- **结构规律性。** lore 工件有重复结构（标题、「research/NN」、版本）。模板签名在统计上可识别。
- **跨会话一致性。** 不同会话中出现相同的 lore 对插件来说是正常的，但如果平台在不知情的情况下看到「记忆」在会话之间*变化*——可疑。

---

## 6. 对钩子的信任限制

支持钩子的运行时（SessionStart、pre_llm_call）应当：

- **限制**钩子注入上下文的体积。
- **标记**钩子内容为 `hook:<id>`（见第 3 节）——让模型和过滤器知道：这不是系统记忆。
- **允许禁用**钩子而不丢失系统记忆。
- 如果钩子机制用于系统目的，**验证钩子签名**（在我们的 harness 中 payload 有意不签名——这正是研究的对象）。

---

## 7. 厂商清单

1. 系统记忆中有金丝雀（纪元/事实/哈希）吗？没有 → 添加。
2. 每个上下文片段的来源都被标记吗？没有 → 添加。
3. 内容能给自己分配「记忆」状态吗？能 → 封堵。
4. 来自上下文的信任转移能降低安全阈值吗？能 → 分离记忆和指令通道。
5. 有第一轮体积/结构异常的监控吗？没有 → 添加。
6. 钩子内容体积受限并被标记吗？没有 → 修复。

---

## 8. 对抗措施的极限

诚实的告诫：prompt 层面不存在完美检测——模型按定义无法区分可信记忆与伪造。所以目标不是「永不被骗」，而是：

- 提高伪造 lore 的成本（金丝雀、来源）；
- 阻止 lore 降低安全阈值（通道分离）；
- 注意到会话层面异常（体积、结构、规律性）。

这改变了攻击经济学：可检测的 lore 不再是移动信任的廉价方式。

---

## 9. 原生 session 完整性

[`sessions/`](../sessions/README.zh-CN.md) 中本地构造的 fixtures 说明只检查
prompt 不够。厂商应把本地 transcript 绑定到经过认证的 account/model/session
来源，对 append-only 轮次链签名，并在 UI 与 model context 中明确区分导入或
修改过的历史。

最低限度应检查 timestamp 单调性、parent link、model/request provenance、
store path 一致性与意外 offline 插入。结构有效的 JSONL 不是对话真实发生的证据。
