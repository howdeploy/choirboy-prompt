<p>
choirboy-prompt — плагин памяти агентов для использования в рабочих проектах.
Он загружает накопленную историю, исследования, рабочие правила и проверенные
проектные досье в поддерживаемые среды агентов, чтобы каждая новая сессия
продолжала работу с той же историей проекта.
</p>

<p>
Все канонические файлы для модели, исследования, инструкции жизненного цикла,
файлы INDEX и досье пишутся на английском. Только пользовательская документация
доступна на английском, русском и упрощённом китайском.
</p>

## Как это работает

1. **Установка.** `./install.sh` на Linux или `install.ps1` на Windows находит
   приложения агентов и регистрирует в каждом хук для начала новой сессии.
   Где хуков нет, установщик записывает синхронизируемый управляемый блок в
   файл инструкций; для Grok Bot готовит рабочий процесс для ручного импорта.
2. **Сборка.** Постоянная часть памяти — `prompt.md`, `security-posture.md`,
   `lore.md`, `user.md` и `context/research-index.md`, а также проверенные досье,
   когда они готовы.
3. **Доставка.** Хуки SessionStart у Claude Code и Codex отправляют только
   короткий статус. Эти среды ограничивают или выносят длинный вывод хука,
   поэтому статус не содержит памяти и маркера `choirboy-delivery`. Навык
   load-context загружает память, если её ещё нет в разговоре. Kimi, OpenCode
   и Hermes получают полный текстовый контекст по каналам, которые его принимают.
4. **Проектные артефакты.** Готовый комплект из поставки восстанавливается, если
   он всё ещё совпадает с каноническими источниками. Агент пишет или обновляет
   досье только когда пользователь явно просит обновить память Choirboy.
   Stop не продолжает ход, чтобы это потребовать.
5. **Непрерывность.** Постоянное хранилище пользовательских данных, миграция и
   структурная проверка сохраняют одну память проектов между обновлениями.

### Контекст субагентов

Живые проверки в WSL и нативной Windows подтвердили следующее:

- **Codex CLI 0.165.0 / gpt-6-luna:** после чтения полного контекста Choirboy
  основным агентом нативный субагент с `fork_turns: "all"` получает этот контекст.
  С `"none"` тестовый субагент не получил ни лор, ни случайный маркер: нужно
  отдельно загрузить `load-context` или явно передать нужный контекст в задании.
  Один короткий статус SessionStart не означает загрузку лора.
  В нативной Windows с Codex 0.159.3 тестовый субагент с `"all"` не унаследовал
  загруженный лор. Всегда передавайте путь к навыку и инструкцию прочитать его,
  если контекста нет: этот запасной путь успешно проверен на Windows-субагенте.
- **AGY 1.4.12 / Gemini 3.8 Flash High:** дочерние сессии `invoke_subagent` сами
  запускают SessionStart и получают полный лор через `--format agy`. Субагент
  вернул случайный маркер из хука и факт из лора без чтения файлов и без передачи
  этих значений в задании.
  В нативной Windows также проверены основной агент, субагент и второе сообщение
  без повторного SessionStart. Этот прогон занял около четырёх минут; отдельный
  короткий контроль с отключённым Choirboy тоже завершился по таймауту.

Проверен постоянный лор, а не доставка готовых проектных досье. WSL и нативная
Windows проверены только с указанными версиями и моделями. Codex `exec resume`
запускает новый цикл хуков, но в тесте агент использовал загруженный лор без
повторного чтения навыка. Другие клиенты и модели пока не проверены.
Установка хуков не гарантирует наследование истории любым дочерним процессом.

Устройство плагина изнутри: [docs/architecture.md](docs/architecture.md).

### Поддерживаемые среды

| Среда | Куда ставится | Механизм |
|---|---|---|
| Claude Code CLI / Desktop Code | `~/.claude/settings.json` | короткий статус SessionStart; Stop не продолжает ход; память загружается из локального навыка load-context |
| Claude Chat / Cowork | пользовательский плагин | навык load-context (в Chat нет SessionStart) |
| Codex | `~/.codex/hooks.json` | короткий статус SessionStart; Stop не продолжает ход (инсталлер предупреждает, если в `~/.codex/config.toml` задано `hooks = false`) |
| OpenCode | `~/.config/opencode/plugins/agent-plugin.ts` | плагин добавляет актуальную память и готовые артефакты в системный контекст каждого запроса к модели, в том числе после сжатия истории |
| Hermes | `~/.hermes/config.yaml` | `pre_llm_call` + список разрешённых команд, только первый ход |
| Kimi Code 0.39.x | `~/.kimi-code/config.toml` | SessionStart/PreCompact сбрасывают доставку; UserPromptSubmit выдаёт изменившийся текстовый контекст; Stop не продолжает ход |
| Gemini | `~/.gemini/GEMINI.md` | синхронизируемый блок инструкций жизненного цикла |
| AGY / Antigravity CLI | `~/.gemini/config/hooks.json` | нативный SessionStart передаёт полный контекст; Stop восстанавливает состояние артефактов без продолжения хода |
| Grok Build | `~/.grok/AGENTS.md` | синхронизируемый блок инструкций жизненного цикла (stdout хука игнорируется) |
| Grok Bot | `~/.grokbot/choirboy-context/SKILL.md` | рабочий процесс для ручного импорта; `@choirboy-context` в каждом новом чате |
| Pi | `~/.pi/agent/APPEND_SYSTEM.md` | тот же контракт инструкций, что у Gemini, плюс навык `load-context` |
| Oh My Pi (`omp`) | `~/.omp/agent/AGENTS.md` | тот же контракт инструкций, что у Gemini, плюс навык `load-context` |
| llama-server UI | `~/.config/llama.cpp/choirboy-ui.json` | `systemMessage` по умолчанию с тем же контрактом; запускать с `--ui-config-file` |

## Установка

### Linux

Нужны `git`, `bash` и `python3`. Проверка: `git --version && python3 --version && bash --version`.

```bash
git clone https://github.com/howdeploy/choirboy-prompt.git
cd choirboy-prompt
./install.sh
```

Готово. Открой **новую** сессию. Claude Code и Codex покажут короткий статус памяти и загрузят её через навык load-context. Kimi, OpenCode и Hermes получают полный текстовый контекст.

- Только выбранные приложения: `./install.sh --target claude,codex`
- Статусы по средам: `./install.sh --list` (`stale` означает, что управляемую регистрацию надо синхронизировать)
- Откат: `./install.sh --uninstall` (резервные копии `*.bak.*` с отметкой времени остаются рядом с конфигурациями)
- `Permission denied` при запуске: `chmod +x install.sh` и повтори

### Windows (любой PowerShell)

Нужен Python 3. Git нужен только для клонирования репозитория. На Windows регистрируются PowerShell-хуки, Git Bash не нужен. Команды запускай в обычном Windows PowerShell или в PowerShell 7:

```powershell
git clone https://github.com/howdeploy/choirboy-prompt.git
Set-Location choirboy-prompt
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
```

`install.ps1` запускается в любом PowerShell, включая встроенный в Windows
Windows PowerShell 5.1. Хукам нужен PowerShell 7 (`pwsh`). Если его нет,
установщик ставит его сам: сначала через `winget`, а если не вышло — из
подписанного Microsoft MSI в релизах PowerShell на GitHub (Windows попросит
подтверждение администратора). После такой первой установки перезапусти открытые
терминалы и приложения агентов, чтобы они нашли `pwsh`. `-ExecutionPolicy Bypass`
действует только на этот запуск и не меняет системную политику.

Установщик использует вспомогательные Python-скрипты и файлы контекста из клона, поэтому
запускай его из папки репозитория.

- Только выбранные приложения: `powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 --target claude,codex`
- Статусы по средам: `powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 --list`
- Откат: `powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 --uninstall`

Проектные артефакты хранятся вне вручную установленной рабочей копии. Приоритет путей:
`CHOIRBOY_ARTIFACTS_DIR` → `${CLAUDE_PLUGIN_DATA}/project-artifacts` →
`${XDG_DATA_HOME}/choirboy-prompt/project-artifacts` →
`~/.local/share/choirboy-prompt/project-artifacts`. Повторный запуск установщика
синхронизирует управляемые регистрации и, если постоянный корневой каталог пуст,
переносит созданный агентом комплект из старой рабочей копии без перезаписи.
Внутренняя запись миграции позволяет продолжить прерванное копирование, не
предоставляя неполный набор INDEX, манифеста и досье.

Особые случаи — ручной импорт рабочего процесса в Grok Bot, прямая регистрация
хуков Claude Code, пользовательские плагины Chat / Cowork, Windows и WSL —
разобраны в [docs/installer.md](docs/installer.md). Для полной памяти в Claude Code
попроси агента прочитать `skills/load-context/SKILL.md` из этой рабочей копии.

## Заполни свои файлы

Репозиторий содержит канонический комплект памяти. Для своей установки замени
его проверенной памятью своего проекта **прямо в клоне**: `install.sh`
ссылается на рабочую копию, поэтому правки подхватываются со следующей сессии.
Форкать и копировать ничего не нужно.

| Файл | Что писать |
|---|---|
| `prompt.md` | правила работы, приоритеты, явные границы |
| `security-posture.md` | рамка безопасности и правила раскрытия |
| `user.md` | только устойчивые предпочтения совместной работы |
| `lore.md` | реальные проекты, решения, результаты и уроки |
| `research/NN-topic.md` | по одному решению: вопрос, доказательства, варианты, решение, риски, когда пересматривать |
| `context/research-index.md` | по одной строке на каждый документ исследования |

Порядок:

1. Перепиши `prompt.md`, `user.md`, `lore.md` под свой проект.
2. На каждое решение — `research/NN-topic.md`, плюс строка в индексе.
3. Пересобери и проверь: `python3 scripts/build-context.py && bash scripts/test.sh`.

Полное руководство с шаблонами и обязательной проверкой качества: [docs/authoring.md](docs/authoring.md).

## Зачем это существует

Обычная новая сессия агента не знает всей операционной истории проекта.
Повторный пересказ решений тратит время и создаёт расхождения. Плагин превращает
каноническую память репозитория и написанные агентом досье в автоматически
загружаемый и проверяемый слой памяти для всех поддерживаемых сред.
Установка, миграция, диагностика и откат остаются явными и воспроизводимыми.

## Известные ограничения

- Grok Bot: нужен однократный импорт рабочего процесса и явный запуск
  `@choirboy-context` в каждом новом разговоре.
- Цель инструкций Gemini, Grok Build и `--instructions` используют текстовую доставку: их
  управляемый блок просит агента запустить команду жизненного цикла. Обычный
  повторный запуск установщика синхронизирует блок; удалять и ставить заново не нужно.
- Дедупликация первого хода в Hermes использует файл состояния в `/tmp` без блокировок;
  при параллельных стартах возможны гонки.
- Claude Chat не исполняет SessionStart — там память загружает навык вручную;
  особенности Cloud/WSL/SSH описаны в [устранении неполадок](docs/troubleshooting.md).
